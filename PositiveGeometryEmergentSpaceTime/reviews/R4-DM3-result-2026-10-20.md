## 3. Surprises and defects (declared, not patched; locked files stay)
1. **Import test breaks after the push.** `sims/r4dm3/import_guard_test.py` calls `hyp_literals` with a stub dict that
   lacks the new key `sm_literals_hyp_E1`. Before the push the guard refuses first, so the recorded refusal is correct
   (exit 2, three REFUSED, no pass flag). After the push the call gets past the guard and the test dies with
   `KeyError` (exit 1) instead of exiting 0. This is a test-harness defect only: the guard is unaffected, and the
   no-pass-flag property was shown before the push. A v4 should use `cls.get('sm_literals_hyp_E1', [])`.
2. **E1/E2 hits inside NO-GEOMETRY rows (no effect on verdicts).** E1 hits two hypotheses, and E2 hits none.
   - `STRUCT1b.yukawa_majorana` (hL : 3·yQ + yL = 0) is a genuine integer-form charge relation, correctly flagged.
   - `STRUCTNGen.sm_core_not_forced` (N ∈ {1, 2, 4, 5}) is a false-positive shape: N is the generation count
     (tier-Q vocabulary), not a charge.

   Both rows are decided NO-GEOMETRY before the smuggling tests run, so neither verdict moves. The live tree has no
   hypothesis with N_c·yQ. FRMU's yQ = 1/(2N_c) appears in definitions and conclusions, not in hypotheses.
3. **E1 limits** (in the prereg): the integers 1 and 2 are not flagged, so an integer-form smuggle of only yQ = 1 or
   yd = 2 would slip. Tier-C variables are exempt, so a charge typed into a coupling-named variable would also slip.
   The vocabulary decides the tier.
