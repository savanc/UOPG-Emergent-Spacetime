## JORD-1: dim_ℚ Der(J3(O)) = 52

`derSub` is the ℚ-subspace of 27×27 matrices D with D(x∘y) = Dx∘y + x∘Dy, for the `PositiveGeometryEmergentSpaceTime.Jord1`
structure-constant table. The map `phi : derSub →ₗ ℚ^52` reads the 52 entries `Fr`.

* **Injective (upper bound).** Peeling certificate: 677 steps. Each step takes a derivation constraint row
  (i, j, k) in which every listed entry is already known to vanish, except the target, whose coefficient is
  nonzero. The certificate is checked as 28 chunks of 25 steps (`Jord1DerPeel.chunk_m`, each `decide +kernel`,
  soundness lemma `peelC_sound`) plus 9 coverage blocks of 81 entries (`cov_r`), giving `peel_zero`.
* **Surjective (lower bound).** There are 52 explicit integer basis derivations G_t = dB[t]⁻¹·B[t], with
  denominators in {1, 2} and 858 nonzeros in total. Each passes `derOK t` (transpose, derivation and Fr-delta
  checks), proved as `Jord1DerB0..B3.der_t` (13 per file, `decide +kernel`).
* `finrank_der` follows from `LinearEquiv.ofBijective`.
* Planted check: `planted_chunk` shows that chunk 1 fails from `Fr` alone.

Earlier failures, kept on record:

1. A single `decide +kernel` on the whole certificate hit a global OOM at 12.4 GB RSS (session interrupted).
2. The first chunked run failed honestly at chunk 25 (steps 645 and 648). Rows (18, 2, 18) and (26, 0, 26)
   list an entry twice with cancelling coefficients. The Python peeler had used net supports; the Lean
   checker uses listed supports. The fix is in the generator, not the checker: the peeler now uses the listed
   (`rowS`) support. F, the rank and the basis are unchanged.

Python cross-check: rank mod p = 1000003 is 677 out of 17445 rows, so the kernel dimension is 52
(`tools/alignment/out/jord1_der_cert.json`).

Regenerate with `tools/alignment/jord1_der_gen.py` and then `jord1_der_split.py`. The output is
byte-identical to the committed files (checked).

**Scope.** This proves dim Der = 52, which equals dim f4. The isomorphism Der ≅ f4 is not formalised.
